# 案例专题 知识点与考点

> **依据**：《26.10 案例专题》讲义全 123 页（第一篇 答题技巧 P2、第二篇 十二个考点专项训练 P4–P88、第三篇 实战练习参考答案 P89–P123）＋ 参考资料《案例万金油找茬技巧》。
> **本书定位**：案例分析**不是"知识题"，是"按点给分题"**。同一个知识点，答题格式不同，得分能差一半。本册解决三件事：**①怎么审题找到考点；②怎么组织答案句式；③十二个考点的"常见问题清单"直接当答案背**。
> **一句话总纲**：**先定位领域 → 再按"过程/工具/人员/制度"四维度找问题 → 最后按"问题＋依据＋对策"分点写。**

## 一、考试形式与评分规则

- 案例分析通常是 **3 道大题**，每题下含 **2–4 个小问**，小问分值 3–12 分不等；
- **按点给分**：答案写到"点"上就给分，**多写不扣分**（除非明显错误）；
- 题型有六种：**找错（指出存在的问题）／判断正误／单项选择／简答（列举）／计算／措施建议**；
- 计算题**按步骤给分**：公式写对、过程对，最后结果错也能得分。

## 二、答题铁律（讲义 P2 原文的"答题方法总结"＋"拿分技巧"）

### 1. 五条答题方法（原文）

1. **分点写，每点写一句**——按点给分，这样写讨巧；时间允许时尽可能多罗列点，**多写不扣分**；
2. **结合实际工作思考**——想想公司实际怎么处理这类问题，也可以写上去；
3. **"问题原因 + 对策"模式**——先看资料，总结做法有什么问题、原因是什么、有什么对策；
4. **审题最重要**——给定资料要**逐词逐句读，基本上每句对应 1–2 个考点**；
5. **计算题尽量算对，写出关键公式和步骤**，答案错也可能给步骤分。

### 2. 三个拿分技巧（原文）

1. **写上能想到的所有答案**——脑子里有好几个答案就都写上，分点写；
2. **不会也不要留白**——答到点上就有分，往相关知识点靠拢；
3. **答题要有次序**——123 点、abc 分列，阅卷老师才看得清。

### 3. 我补充的两条

4. **先写结论再写理由**：如"存在的问题：①……②……"，不要写成一大段散文；
5. **一问一答，不串题**：第 2 问问"如何应对"，就别把第 1 问的"存在的问题"再抄一遍。

## 三、审题四象限（万金油总框架，讲义 P3 原表）

拿到案例，先按四个维度扫一遍资料，几乎每个问题都能从这里找到答案：

### 象限 1：从项目管理过程考虑（12 类过程清单）

| 领域 | 过程（按讲义 P3 原文顺序） |
|---|---|
| 整合管理 | 制定项目章程；制定项目管理计划；指导与管理项目工作；管理项目知识；监控项目工作；实施整体变更控制；结束项目 |
| 范围管理 | 规划范围管理；收集需求；定义范围；创建 WBS；确认范围；控制范围 |
| 进度管理 | 规划进度管理；定义活动；排列活动顺序；估算活动持续时间；制定进度计划；控制进度 |
| 成本管理 | 规划成本管理；估算成本；制定预算；控制成本 |
| 质量管理 | 规划质量管理；管理质量；控制质量 |
| 资源管理 | 规划资源管理；估算活动资源；获取资源；建设团队；管理团队；控制资源 |
| 沟通管理 | 规划沟通管理；管理沟通；监督沟通 |
| 风险管理 | 规划风险管理；识别风险；实施定性风险分析；实施定量风险分析；规划风险应对；实施风险应对；监督风险 |
| 采购管理 | 规划采购管理；实施采购；控制采购 |
| 干系人管理 | 识别干系人；规划干系人管理；管理干系人参与；监督干系人参与 |
| 配置管理 | 编制配置管理计划；配置标识；配置控制；配置状态报告；配置审计；配置管理回顾与改进 |
| 变更管理 | 提出申请；初审；论证；审查；通知实施；监控；效果评估；收尾 |

> **用法**：案例里"某过程没做/做得不到位"，就写"**未开展/未有效开展 ×× 过程**"，再补一句这个过程的输出没形成（如"未形成范围基准"）。

### 象限 2：从关键词反映问题（讲义 P3 原文映射表）

| 题干出现 | 反映的问题 |
|---|---|
| 客户验收不通过、争执不满意、多头汇报 | **沟通不到位** |
| 新项目、新技术、新员工、第一次 | **有风险、无经验、缺培训** |
| 修改、变更 | **没有走变更控制流程** |
| 之后才发现了问题、延期 | **监控不到位、没有做好控制** |
| 认为、觉得、初步、匆忙、简单、大致 | **缺乏分析、没有具体详细的内容** |

> **用法**：这几个词是"信号弹"。看到"大致""认为"就写"缺乏详细的需求分析与论证"；看到"新员工"就写"缺乏培训与经验，未识别相关风险"。

### 象限 3：从人员方面考虑（5 条）

1. **人员经验**——缺乏经验和技能、培训不到位；
2. **人员态度**——意识淡薄、考虑不周、不愿意合作；
3. **人员安排**——身兼数职、没有安排专职人员；
4. **一人包办**——一个人做规划、一个人审批或没审批、没有集体开会讨论确认；
5. **人员沟通**——没做好沟通、工作混乱、信息发布有问题。

### 象限 4：从制度规范考虑（4 条）

1. **评审、确认、验收、阶段管理**没做或没做到位（没确认没评审、没找干系人确认、没获得一致同意）；
2. **制度不健全或没建立**（如成本管理制度、质量体系、沟通管理机制）；
3. **没有按需求使用对应的工具**；
4. **规则及绩效**（没有共同的规则、不公平、没有绩效考核机制）。

## 四、十二个考点的"常见问题清单"（讲义第二篇 Part1 原表，直接当答案背）

> **说明**：以下每张表都按 **过程 / 工具 / 人员 / 制度 / 其他** 五维整理，**考场上照维度挑 3–6 条写**，命中率极高。带 ★ 的是最高频。

### 考点二 整合管理（P7–P13）

| 维度 | 常见问题 |
|---|---|
| **过程** | ★没有制定项目整体管理计划；★整体管理计划不是简单合并，需要相互协调；执行不到位；★没有做好项目收尾、没有做好经验教训总结；项目监控不到位，没有认真核实可交付成果 |
| **工具** | 项目计划缺少分计划 |
| **人员** | ★计划应该跟团队一起制定（而不是项目经理一人）；项目经理经验不足，缺乏管理经验 |
| **制度** | ★项目计划缺少评审和审批环节；★项目已经变更、基线没有变更；★没有制定整体变更流程；没有处理好内外部因素、制定应对措施；★变更没有走变更流程 |
| **其他** | 没有对项目进行监控和跟踪、及时纠偏；项目变更合同没有相应变更；配置管理没做好、没有做好版本控制 |

> **关键记忆点（原文）**：过程＝章程、计划（全体/评审）、指导与管理、管理知识、**没有走变更控制流程**、监控；子管理角度入手＝进度、成本、沟通、风险、合同、配置等。

### 考点三 范围管理（P14–P21）

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定范围管理计划；没有制定需求管理计划；★没有充分收集需求、没有通过各种渠道进行需求采集；★没有对范围进行清晰定义、范围定义内容不充分；★没有对项目进行工作分解、创建 WBS；范围确认工作不到位；★没有对范围进行有效监控，导致**范围蔓延或镀金** |
| **工具** | 没有制定范围说明书或内容不充分，**缺少制约因素或假设条件**；没有对范围进行实时监控和偏差分析 |
| **人员** | 范围管理计划应由团队成员共同制定，不应只由项目经理一人制定；没有进行有效沟通；项目经理经验不足 |
| **制度** | ★需求没有评审和确认，导致编码、设计不一致；需求没有得到干系人的理解和确认；没有制定变更流程；★需求变更没有走变更控制流程；范围变更没有对合同进行相应变更 |
| **其他** | 没有有效范围管理，导致二次变更 |

> **关键记忆点**：计划（全体/评审）→ 需求（全体确认）→ 范围说明书（全体评审）→ 创建 WBS（100%、基准、评审）→ 确认 → 控制。
> **两个必背术语**：**范围蔓延**＝未经控制的范围扩大；**镀金**＝主动添加客户没要求的功能。

### 考点四 质量管理（P22–P30）

| 维度 | 常见问题 |
|---|---|
| **过程** | ★没有制定质量管理计划或内容不充分；★质量保证不到位或没有实施质量保证；★质量控制不合理、效果不佳 |
| **工具** | 没有使用合适的质量控制工具；测试方法不当或不充分 |
| **人员** | ★项目经理质量管理经验不足；★项目经理或团队成员缺乏质量意识；★质量职责分配不合理、**没有独立于项目组的 QA 或 QA 没有全程参与**；没有为质量管理员提供培训；身兼多职、顾此失彼；与客户沟通存在问题、沟通方式单一；没有按变更控制流程对质量进行变更 |
| **制度** | 没有制定质量保证体系；缺乏质量标准和规范；★需求评审没有客户参与；★重大里程碑处没有设置阶段评审；★质量控制缺少必要环节（评审、测试） |

> **关键记忆点**：**专职、意识、体系、标准、规范、经验**。
> **必须区分**：质量管理计划（规划质量管理输出）／管理质量（=质量保证，过程审计，用质量审计、过程分析、DfX）／控制质量（检验可交付成果，输出**核实的可交付成果**）。

### 考点五 资源管理（P31–P37）

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定资源管理计划；没有制定人员储备计划；团队组建不合理；★团队建设工作没有做好、没有管理好团队；没有控制资源 |
| **工具** | ★职责分配存在问题、导致相互推诿；没有进行相关的团队建设活动；★冲突管理没有做好、成员矛盾不断；绩效管理没有做好、没有激励政策 |
| **人员** | 资源管理计划应由团队成员共同制定；项目经理经验不足；团队缺乏沟通 |
| **制度** | ★团队目标不明确、成员岗位不明确；没有成文或习惯的工作流程和方法；★没有明确的考核和评价标准、赏罚不透明；没有协同工作、没有组织纪律 |

> **关键记忆点**：计划（全体/评审）、获取（储备）、估算、建设、管理（冲突）、控制；**岗位—目标—职责—流程—考核—纪律**。

### 考点六 沟通管理与干系人管理（P38–P45）

**沟通管理：**

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定沟通管理计划；★沟通工作不到位；控制沟通工作没有做好 |
| **工具** | 没有针对干系人的沟通需求和沟通问题进行分析；★没有根据实际情况选择相应沟通渠道；没有对沟通情况进行记录；没有制定相应的沟通模板 |
| **人员** | 沟通管理计划应由团队共同制定；没有根据实际情况进行有效沟通；人员经验不足、沟通不到位；没有对沟通问题及时解决 |
| **制度** | ★沟通需求没有得到干系人的理解和确认；沟通方法选择不合适 |

**干系人管理：**

| 维度 | 常见问题 |
|---|---|
| **过程** | ★没有识别干系人或识别不全面；没有制定干系人管理计划；没有管理干系人参与；控制干系人参与没做好 |
| **工具** | 没有针对不同干系人进行分析；★没有针对不同干系人选择不同沟通方法及频率 |
| **人员** | 干系人管理计划应由团队共同制定；项目经理经验不足 |
| **制度** | 没有对干系人进行**权力-利益分析**；★没有将所有干系人都纳入干系人登记册；没有对不同的干系人提交各自需要的信息 |

> **关键记忆点**：沟通过程＝计划、管理、监督；干系人过程＝识人、计划、管理、监督；**需求-模板-技巧方法-频率渠道**。

### 考点七 采购与合同管理（P46–P54）

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定采购管理计划；实施采购过程没做好；★控制采购没做好、没有实时监控卖家绩效并采取必要措施；结束采购没做好、没有对文档归档及总结经验教训 |
| **工具** | ★没有编写采购工作说明书（SOW）；没有进行自制外购分析；★没有供应商选择标准、选择过于随意 |
| **人员** | 项目经理不重视采购管理；沟通存在问题 |
| **制度** | 采购流程制度不规范；★没有做好货物验收工作；★合同中未规定**索赔和违约责任** |
| **其他** | 没有综合考虑进度与货物交付时间；库存规划不合理；★未记录采购过程文件和往来凭证 |

> **关键记忆点**：规划、实施、控制；招投标 → 调查 → 合同（签订、付款方式、**违约责任**、验收标准）→ 记录。

### 考点八 配置管理（P55–P60）

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定配置管理计划；★配置管理过程中没有做好相应记录；未制定配置管理权限机制、配置管理混乱 |
| **工具** | 未进行配置工具的使用和培训；★没有建立基线，导致需求、设计无法对应 |
| **人员** | ★未设置专门的配置管理员（CMO）；★配置管理计划**不应由 CCB 制定**；★变更发布应交由 **CMO**；身兼多职；配置管理人员经验不足 |
| **制度** | 没有定义配置管理流程；★没有做好整体版本控制管理；没有做好变更管理；变更基线流程缺少变更验证 |

> **关键记忆点**：过程＝计划、识别、控制、状态、审计；**专职、版本管理、基线、配置库权限**。
> **两个高频陷阱**：①配置管理计划由**配置管理员（CMO）**编制、由 **CCB 审批**，不是项目经理；②**变更的发布由 CMO 执行**。

### 考点九 变更管理（P61–P66）

| 维度 | 常见问题 |
|---|---|
| **过程** | ★没有提交变更**书面申请**；★没有对变更影响进行完整分析和评估；★**没有组织 CCB 审查**变更申请；没有实施变更；★没有监控变更实施；没有变更记录形成文档；★没有修改项目管理计划 |
| **人员** | 没有将变更影响通知干系人；没有遵循变更控制流程；没有认真审核变更；★变更控制委员会组成成员不合理 |
| **制度** | 变更结果没有得到客户确认；没有进行变更后评审；★是否接受变更不应该由项目经理决定 |
| **其他** | 版本管理和配置管理没做好；项目变更后合同没有相应变更 |

> **关键记忆点**：**书面申请 → 影响分析 → CCB 审批 → 通知并实施 → 监控 → 记录 → 更新基准/计划 → 效果评估**。

### 考点十 风险管理（P67–P78）

| 维度 | 常见问题 |
|---|---|
| **过程** | 没有制定风险管理计划或内容不全面；★没有全面识别风险；★缺乏定性分析（没有优先级排序、没有概率影响分析）；缺乏定量分析（没有量化风险信息）；★没有制定风险应对计划或措施无效；★风险监控不到位、没有跟踪已识别风险 |
| **人员** | 项目经理或团队成员缺乏风险意识；★风险管理不应只由项目经理一人参与，**全体团队成员和干系人应共同参与**；项目经理风险管理经验不足；缺乏沟通产生不必要的风险 |
| **工具** | ★没有制定风险登记册；缺乏有效的风险监控工具；没有对风险再评估、审计及偏差趋势分析 |
| **制度** | 没有做好技术绩效测量工作、及时评估与绩效对比；没有对进度风险及关联影响进行充分评估 |

> **关键记忆点**：过程＝计划（全体/评审）→ 识别（全体/反复）→ 定性 → 定量 → 规划应对 → 实施 → 监督；**专职、意识、工具**。

### 考点十一 收尾管理（P79–P85）

收尾题的套路只有一个：**把题干里的每个"动作"和标准动作对照，凡是不符合规程的都是错误**。常见错误清单：

1. **系统测试**：没有按合同约定的系统环境**全面测试**（只挑部分数据测试＝错）；
2. **试运行**：只加载数据运行，**缺少用户日常操作的问题跟踪与维护**；
3. **文档移交**：文档**未经验收合格、未经双方签字确认**就直接发送（错）；
4. **项目验收**：验收报告应由**双方项目组共同撰写**并提请双方工作主管认可（一人代写＝错）；
5. **总结**：只列优点、**没有列缺点和经验教训**（错）；
6. **总结会**：总结报告必须由**全体成员共同讨论确认**（只叫部分人＝错）；
7. **移交对象**只做了一个（应向用户、向运维支持团队、向组织分别移交）；
8. **过程资产未归档**。

> **三类移交清单（原文，必背）**：
> - **向用户移交**：需求说明书、设计说明书、项目研发成果、测试报告、可执行程序及用户使用手册等；
> - **向运维和支持团队移交**：需求说明书、设计说明书、项目研发成果、测试报告、可执行程序、用户使用手册、**安装部署手册或运维手册**等；
> - **向组织移交过程资产**：项目档案；项目或阶段收尾文件；技术和管理资产。

## 五、六类题型的答题模板

### 模板 1：找错类（"请指出存在的问题"）

```
存在的问题：
（1）××××（问题本身）——依据：应××××（讲过的规程/应做的过程）；
（2）……
（3）……
建议：（可选）针对上述问题，应××××。
```
> **提分点**：每条尽量 **"错在哪 + 应该怎样"** 两段式。只写"没有做变更管理"得 1 分；写"没有提交书面变更申请、未经 CCB 审批即实施变更"可得 2–3 分。

### 模板 2：措施类（"如何改进/如何应对"）

```
针对上述问题，建议采取以下措施：
（1）制度/流程层面：建立并执行××流程（如整体变更控制流程），明确××职责；
（2）过程层面：补做××（如补充需求确认、重新评审范围基准、更新风险登记册）；
（3）人员层面：安排专职××、开展××培训、明确分工与考核；
（4）工具/技术层面：采用××工具（如挣值分析、质量审计、配置管理工具）；
（5）沟通层面：与客户/干系人确认××，按沟通管理计划定期汇报。
```

### 模板 3：判断正误类（"判断下列说法正误"）

```
（1）×。理由：××××（一句话点出正确说法）；
（2）√。
```
> **口诀**：**先写符号，再写一句理由**；只写符号通常只得一半分。

### 模板 4：选择题类（"从候选答案中选择"）

直接写选项字母；若题干要求"并说明理由"，补一句依据。

### 模板 5：简答/列举类（"请简述/列举××的内容"）

**按讲义原文逐条列出**，宁多勿少（多写不扣分）。如"项目建议书内容"＝项目的必要性、项目的市场预测、产品方案或市场服务预测、项目建设必需的条件（**两必两测**）。

### 模板 6：计算类

见《计算专题 知识点与考点》——公式 → 代入 → 结果 → 判断四步。本题库里 90% 是 **PV/EV/AC + CV/SV/CPI/SPI + 典型/非典型 ETC/EAC**。

## 六、高频"标准表述"弹药库（背下来直接套）

| 场景 | 标准表述 |
|---|---|
| 变更没走流程 | 未提交书面变更申请；未经变更控制委员会（CCB）审查批准即实施变更；变更后未更新项目管理计划与基准，未通知相关干系人 |
| 需求没确认 | 需求未经过评审与客户确认即进入设计/编码，导致返工与范围蔓延 |
| 计划一人编 | 项目管理计划应由项目团队共同参与制定，并经评审批准，不能由项目经理一人编制 |
| 没有基线 | 未建立范围/进度/成本基准，导致无法据此度量偏差 |
| 质量与 QA | 未设置独立于项目组的质量保证人员（QA），未开展质量审计；质量控制缺少评审与测试环节 |
| 风险登记册缺失 | 未建立风险登记册，未对风险进行概率与影响分析，未制定应对策略与责任人 |
| 干系人登记册缺失 | 未全面识别干系人，未做权力-利益分析，未纳入干系人登记册 |
| 采购与合同 | 未编制采购工作说明书（SOW）与供方选择标准；合同中未约定验收标准、付款方式、违约责任与索赔条款 |
| 配置管理 | 未设置专职配置管理员（CMO），未建立配置库与基线，未开展配置审计与状态报告 |
| 收尾 | 未按合同约定进行全面测试；文档未验收签字；验收报告未由双方共同编写；总结会未全员参与、未总结教训 |
| 经验教训 | 未开展经验教训总结与归档，组织过程资产未更新 |
| 沟通 | 未制定沟通管理计划，未识别干系人信息需求，导致多头汇报、信息不一致 |

## 七、真题精讲（讲义第二篇 Part1 例题＋实战练习）

### 例 1：WiMAX 无线网络案例（P4，考点一）

**案情要点**：集团要建覆盖 15 公里的无线网络，张某上网搜索后选定 B 公司的 WiMAX 产品，实地考察、演示后就签采购合同并部署。投运后出现覆盖盲区、不支持部分数据业务、用户多时速率骤降、莫名断网；无线电管理部门因其**未取得频带使用执照**要求停用并处罚；B 公司即将退出中国大陆，技术支持困难。

**问题 1（6 分）**：张某未进行充分可行性研究，体现在哪些方面？（A 投资必要性 B 技术可行性 C 财务可行性 D 组织可行性 E 社会可行性 F 经济可行性 G 风险因素分析及对策）
> **答案：B、E、G**。
> **解析**：①技术可行性缺失——没有对覆盖范围、数据业务类型、并发速率做技术验证；②社会（环境）可行性缺失——未了解无线电频率使用许可的政策法规；③风险因素分析及对策缺失——未评估供应商退出、技术支持中断的风险。

**问题 2（3 分）**：项目建议书的主要内容。
> **答案**：项目的必要性；项目的市场预测；产品方案或市场服务预测；项目建设必需的条件（**两必两测**）。

**问题 3（6 分）**：如何应对当前困境。
> **答案（五段式，原文）**：①了解无线电频带使用的有关政策，与政府有关部门沟通，商谈办理频带使用手续；②与 C、B 公司沟通寻求技术解决方案，针对速率、多数据类型、断网、覆盖盲区等问题商议满足需求的方法和措施；③与 C 公司就系统后续技术支持和服务沟通协商；④若协商不成，依据合同让 C 公司承担相应责任，或提出替代方案、终止项目；⑤将风险管理纳入日常工作，建立风险预警和管理机制。

> **提分要点**：问题 3 这类"应对措施"题，**按"政府/供应商/合同/技术/管理"五个维度分点**，正好对应答案五条。

### 例 2：甲公司立项案例（P5，考点一实战）

**案情要点**：甲公司战略规划部起草立项申请→总经理批准→开展初步可研（只粗略调研政策、市场、成本）→依初步可研就决定上马、成立工作小组公开招标；乙公司成立不足两年，由软件工程师郑工**从技术角度独立编制投标文件**；中标后合同谈判在违约金、项目边界、交付质量标准上分歧大，最终未签约，甲公司另选他家。

**问题 1（6 分）**：甲公司在项目立项时存在哪些问题？
> **答案要点**：①**未开展详细可行性研究**，仅凭初步可研就决定上马（详细可研不可省略）；②初步可研内容不全面、**缺少定量描述**（如实施进度、投资估算、经济评价）；③立项**未经项目评估**（第三方评估）即决策；④招标文件/合同条款（违约金、范围边界、质量标准）**未在招标前明确**，导致谈判破裂；⑤**未进行风险分析**（对投标人能力、交付风险无评估）；⑥项目范围与验收标准未在招标文件中清晰界定。

**问题 2（6 分）**：乙公司在项目立项时存在哪些问题？
> **答案要点**：①投标文件由**一名技术人员独立编制**，缺乏商务、管理、财务人员参与，**未经评审**；②仅从**技术角度**分析可行性，未做经济、管理、风险可行性分析；③对招标文件的**范围、质量标准、违约责任**未充分评估即投标；④投标决策未经公司层面审批，**风险识别不足**。

**问题 3（6 分）**：项目管理原则"勤勉、尊重和关心他人"的关键点。
> **答案**：①关注组织**内部和外部**的职责；②坚持**诚信、关心、可信、合规**原则；③秉持**整体观**，综合考虑财务、社会、技术和可持续发展环境等因素。

### 例 3：B 公司办公系统整合案例（P6）

**问题 1（8 分）**：项目在**立项管理**和**需求管理**方面存在的问题。
> **立项管理**：①未做可行性研究（技术/经济/管理/风险）即决定采购成熟系统；②项目目标（3 个月完成）**未经论证**，进度约束不合理；③未进行**自制外购分析**与供应商评估（C 公司无国内网络资源与资质）；④合同**未约定验收标准、性能指标与违约责任**；⑤项目经理由 HR 总监兼任，**缺乏项目管理经验与专职配置**。
> **需求管理**：①需求说明书由**供应商单方编写**，未经甲方评审确认；②未收集最终用户（员工）需求，未做**原型/演示验证**；③未识别本地化、语言文化差异等**非功能需求**；④需求变更（追加 CDN）未走**变更控制流程**，直接追加费用。

**问题 2（5 分）**：需求文件的主要内容。
> **答案**：业务需求、干系人需求、解决方案需求（功能需求＋非功能需求）、过渡需求、项目需求、质量需求（讲义 P114 六类）。

**问题 3（5 分）**：判断正误。
> （1）项目建议书也可与可行性研究报告合并，报送项目审批部门——**√**（小项目可省略建议书环节，与可研合并）；
> （2）初步可行性研究报告比较粗略，不对项目进行全面的描述分析——**×**（初步可研报告虽粗略，但对项目已有全面描述、分析和论证）；
> （3）作为系统集成供应商，需要在组织内为签署的设备采购类项目单独立项以确保对合同责任加以约束和规范——**√**；
> （4）只有通过初步可行性研究认为项目基本可行后，才会开展详细可行性研究工作——**√**；
> （5）项目评估是由第三方对拟建项目进行评价、分析和论证，目的是审查可研结论是否客观、真实、可靠——**√**。

### 例 4：项目收尾案例（P83–P85，考点十一实战）

**案情**：小张团队做了六项工作——①系统测试（只挑部分数据测试）；②试运行（只加载数据运行）；③文档移交（把最终报告、项目介绍、说明手册、维护手册、软硬件说明书、质量保证书直接发给业主）；④项目验收（派小李撰写验收报告发给双方主管）；⑤准备总结会（只总结了过程文档与技术人员经验、只列优点）；⑥召开总结会（只召集部分人员讨论并形成总结报告）。

**问题 3（12 分）**：哪些工作存在问题并说明。
> **答案（原文）**：①工作一，应根据双方合同约定的系统环境**进行全面测试**；②工作二，试运行还应包括**用户日常操作的问题跟踪维护**；③工作三，系统所有文档都应**验收合格并经双方签字确认**；④工作四，应由**双方的项目组**共同撰写验收报告并提请双方工作主管认可；⑤工作五，应进行**全面总结**，不仅列优点，也要列**缺点和经验教训**；⑥工作六，总结报告必须由**参与项目的全体成员**一起讨论确认。

## 八、综合类案例解题流程（考点十二 P86–P88）

```
第 1 步  看问题（先看问什么，再读材料，带着问题读）
第 2 步  读材料并逐句标注异常（用四象限：过程/关键词/人员/制度）
第 3 步  把异常按领域归类（范围？进度？质量？沟通？配置？变更？）
第 4 步  每个领域套用"常见问题清单"，挑 2–3 条最贴合题干原文的
第 5 步  按"问题＋依据（应怎样）＋对策"分点作答
第 6 步  计算小题单独用《计算专题》四步法
第 7 步  检查：是否答了"问什么"？有没有漏掉多问？分点编号是否清楚？
```

> **综合题的得分规律**：**领域越全、点越多，得分越高**。宁可写 8 条（其中 3 条不完全对），也不要只写 3 条标准答案。

## 九、自测 10 题（答案在后）

**1.** 案例答题为什么"多写不扣分"？基于这个规则应该怎么答？

**5.** 项目收尾的三类移交对象分别是什么？各移交哪些内容？
**6.** 质量管理的 QA 为什么必须"独立于项目组"？
**7.** 采购合同里必须约定的关键条款有哪些（至少 4 项）？
**8.** 范围蔓延与镀金的区别？
**9.** 综合类案例题的解题 7 步是什么？
**10.** 判断题只写"√/×"会怎样？应该怎么写？

<details><summary>答案</summary>

1. 案例**按点给分**，标准答案 3 条而答 5 条，只要多出的没有明显错误就不扣分；因此应**分点、多列、往知识点靠拢、绝不空题**。
2. 反映**缺乏分析、没有具体详细的内容**（需求没做细、方案没论证、计划没细化）。
3. ①**没有书面变更申请**；②**未经 CCB 审查批准**就实施；③变更后**未更新计划/基准、未通知干系人、未记录**。
4. 配置管理计划由**配置管理员（CMO）**编制、由 **CCB 审批**；变更发布由 **CMO** 执行。
5. 向**用户**移交（需求说明书、设计说明书、研发成果、测试报告、可执行程序、用户手册）；向**运维和支持团队**移交（上述＋**安装部署/运维手册**）；向**组织**移交过程资产（项目档案、收尾文件、技术和管理资产）。
6. 只有独立于项目组，QA 才能**客观审计过程是否符合质量政策与标准**，不受项目进度与成本压力影响，否则"自己监督自己"形同虚设。
7. 采购内容与**SOW**、**验收标准**、**付款方式与进度**、**交付时间**、**违约责任与索赔**、变更与争议处理、知识产权与保密。
8. **范围蔓延**＝范围未经控制地被动扩大（客户不断加需求）；**镀金**＝团队主动添加客户没要求的功能（"多做了一点"）。
